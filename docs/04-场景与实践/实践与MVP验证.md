# 实践与 MVP 验证

状态：本次知识整理提出的实验框架；待用户按真实业务确认，不是已排期开发承诺。

## 1. 先验证一个闭环

从业务事件进入 → 正确提取候选信息 → 人工确认 → 维护状态/未闭环事项 → 产生可用建议或草稿 → 人工完成/批准受控动作 → 核验结果。首轮可只读/草稿，不要求自动写入或接管企业系统。

目标不是展示“Agent 能调用工具”，而是用户是否少做重复整理、少漏承诺、少维持脑内待办，同时不会增加数据维护负担。[S04 §2–3；S05 §24；S14 关键决策 14、17]

## 2. 实验准入

- 指定一个业务角色、一类工作、清楚的开始/完成条件与责任人。
- 取得数据、系统、实验参与者及用途的必要授权；先用合成/脱敏样本。
- 列出事实源、动作范围、不可执行事项和人工兜底方式。
- 基线用当前流程实测，不能以宣传材料代替。
- 冻结评价集和退出条件，再比较方案。

本框架不授权读取客户系统、发送通信、自动报价、签合同、做人员决策或使用生产数据。

## 3. 建议实验包

| 实验 | 最小产物 | 核验重点 | 否定/暂停条件 |
|---|---|---|---|
| E01 业务发现 | 去敏流程图、事件与责任清单、基线 | 用户说的痛点与实际任务是否一致 | 无稳定频率/收益，责任不可界定 |
| E02 Context 原型 | 来源到对象/事件/状态映射、冲突样例 | 来源可追溯、时效正确、无越权 | 错误合并实体、旧事实污染当前 |
| E03 只读/草稿助手 | 可解释建议、草稿、原文定位 | 人工修正量与总耗时 | 比原流程更累或输出无法信任 |
| E04 受控执行 | 动作提案、批准、回执、撤销演练 | 幂等、授权、失败恢复 | 未批准写入、执行不明、不可恢复 |
| E05 第二组织复用 | Domain Pack/配置差异与实施工时 | 复用确实减少交付成本 | 新客户仍需独立 fork |

E04、E05 仅在前置验证成立且另行获准后开展。

## 4. 指标分开看

- 业务：闭环时间、错漏、返工、等待、响应延迟。
- 用户：总耗时、纠错负担、重复输入、信任、是否仍需自己记。
- Context：实体误合并/误拆分、来源完整率、冲突处理、时效错误。
- 安全：越权读写、敏感输出、提示注入、撤权生效和恢复成功率。
- 系统：端到端成功率、延迟、成本、重试与失败诊断。
- 商业：实施工时、人工兜底、支持与连接器维护成本、愿付价和续用。

不预填没有样本依据的百分比门槛；正式实验前由业务责任人确认阈值、样本构成和判定方法。Billing Metric 与 Value Metric 分离。[S04 §13]

## 5. MVP 记录模板

场景/角色；原流程与基线；证据来源及授权范围；假设；替代方案；数据边界；最小交付；完成标准；样本；结果；失败与反例；成本；适用范围；下一步与停止条件。
