# Kernel、企业 Context 与交付分层

状态：由历史原则重组的候选架构，不是已批准实现。依据：S01 D50–D52、S04 §16–18、S06 §10、S07 §7。

## 1. 统一母结构

资料库与工具库 + 通用 Kernel/壳子 + 行业适配 + 企业 Context/定制 + 运行反馈与内部沉淀。

| 层 | 应承载的内容 | 不应混入 |
|---|---|---|
| 通用 Kernel / Runtime | 稳定的对象与事件契约、来源与时间、工作流接口、权限和动作边界、审计与投影接口 | 特定客户规则、模型供应商细节、行业全部字段 |
| 企业 Context | 已授权组织事实、角色、当前状态、关系、未闭环事项、正式规则和历史决策；推断可独立标注保存 | 员工私人笔记、冒充已确认事实的 AI 推断、跨企业串用信息 |
| 行业 Domain Pack | 术语、本体扩展、常见流程、规则模板、行业评价样例 | 某家企业的秘密、未经验证的通用化结论 |
| 企业定制 | 本地流程、政策、角色关系、连接器配置、数据映射、审批链 | 长期独立代码 fork、绕过核心授权的特殊写入口 |
| Shared Capabilities | OCR、ASR、文件解析/转换、搜索、报表、模型与系统连接器 | 直接成为业务事实源或最终授权者 |
| 内部沉淀 | 可合法复用的模板、工具、评价集、交付手册与 Kernel 改进 | 客户原始业务数据或不属于交付方的知识产权 |

Kernel 不是“先开发一切通用功能”。先用具体工作验证稳定契约，重复模式出现后再抽象；不是把所有行业强行塞入万能 JSON。

## 2. 业务闭环分层

1. 信息入口保留原始来源和采集权限。
2. 解析/抽取产生候选对象、事件和关系，不直接改成事实。
3. Context 维护已确认状态、有效时间、冲突和来源。
4. Context Scheduler 按身份、目的、权限和任务投影工作上下文。
5. Agent 产生解释、建议、草稿或动作提案。
6. 确定性服务校验权限、业务规则和必要批准，再执行获准动作。
7. 核验结果、记录回执，失败时恢复或补偿。
8. Attention Scheduler 决定哪些异常和判断值得交给人。[S05 §3、5–6、13、23]

## 3. 三类 Context 不合并

- Personal：个人偏好、私人生活、个人合法可携带经验与注意力政策。
- Role：岗位责任、业务状态、正式成果、承诺、授权和交接。
- Organization：组织制度、主数据、正式业务事实、流程与治理。

入离职的 Context Binding 是候选模型：授权连接可建立或撤销，不能把员工全部历史导入公司，也不能把前公司的业务 Context 带进新组织。岗位可持续，人可流动。[S01 D30–D34；S05 §7–11]

## 4. 现有软件与通用 Agent

先连接现有系统，不默认替代它们。权威状态必须声明由哪个系统或批准记录负责；模型会话不是默认主数据源。Agent Adapter / API / MCP / Skill 均是可能端口，MCP 不应成为唯一端口或隐性授权通道。[S01 D40–D41；S05 §18–20]

UI 可结合 AI 对话、Attention Feed、结构化工作视图和原始 Evidence。Conversation-first 不等于 conversation-only；批量审核、对比、恢复、权限和时间线仍需要结构化界面。[S05 §12、14、18]

## 5. Brownfield 与 Greenfield

早期概念设计把 ANC 分为两类切入，均是架构母题而非已交付方案：[M01]

- Brownfield：连接既有 ERP/OA/SaaS/Excel/CRM，在它们上方维护有来源的 Context 与协调，不要求先换掉全部系统。
- Greenfield：针对新建工作系统，以自然语言意图、结构化 UI、DB/Event/Evidence 真相层和共享能力层组织体验；不是仅给传统表单增加聊天插件。

能力层候选包括 OCR、STT/ASR、格式转换、解析、模型、Embedding、RAG 和生成能力。无论哪条路线，真相层与概率生成分开，企业流程规则不能直接等同 Agent 推理。

早期垂直项目架构曾讨论 Controlled Extension，即受控扩展而非模型自由改变 Schema/规则/正式写入口。是否及如何采纳到企业 Kernel，仍须通过实际用例与独立决策。[M01]

## 6. 如何决定抽象归属

每次交付复盘：这是企业特例、行业共性、跨行业业务原语、共享能力，还是 Kernel 缺口？保留客户配置与核心代码边界；为可复用资产补来源、许可、适用条件、反例和评价。以实施工时是否下降验证复用，不以模块数量证明产品化。
