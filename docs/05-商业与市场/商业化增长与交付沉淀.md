# 商业化、增长与交付沉淀

状态：长期商业原则与待验证假设，不是价格表、销售承诺、正式商业模式或客户名单。依据：S01 D43–D52；S04；S08 §21–28。

## 1. 先明确现在卖什么

必须回答产品是什么、谁用、谁付、为什么现在付、怎么交付、如何获客、创造什么可观察价值。抽象 Context Platform 或 Agent Society 不能代替可交付的具体工作成果。

验证阶梯：有人需要 → 持续使用 → 愿意付费 → 第二个类似用户可复制 → 获客可重复 → 交付成本下降 → 范围扩张 → 可能形成平台/网络价值。任何一层不成立，都不能靠后面愿景补足。[S04 §2–3]

## 2. 两条增长路径

Top-down：在企业明确授权下从已有系统和流程切入，建立组织 Context，再进入角色与部门。潜在优势是决策与资源集中，风险是实施复杂和员工不采用。

Bottom-up：个人单点价值 → 真实 Shared Artifact/handoff → 协作价值 → 正式组织治理。潜在优势是使用先于采购，风险是个人价值不足、组织转化不确定和隐私边界被侵蚀。

两者是兼容候选，不预设必须选择其中一个。不得通过未经授权的个人数据发现组织并自动合并。[S04 §4–5]

## 3. 客户假设

历史候选 ICP：商业模式已验证、有利润/现金流、正在增长、组织复杂度超出现有管理方式的企业。区域市场可能存在高价值与供给密度的错配，但非一线、SME 和跨行业都还不是被数据证明的最优战略。

客户选择应考察需求、支付能力、访问条件、负责人、预算和采购链，不记录私人关系资源或把可能接触的行业当成已有客户。[S01 D46–D47；S04 §7–8]

## 4. Value Expansion

先解决一类工作，再因可验证价值扩大 Role、Workflow、Connected Systems、治理或自动化范围，带动合同范围扩张。不是“我们觉得更重要了就涨价”。

价值阶梯可从 Visibility（看见状态）到 Coordination（减少同步），再到 Automation（受控执行）和 Optimization（改进运行）。这不是承诺自动上升，安全、组织采用和单位经济性都要逐级验证。[S04 §9–10]

## 5. 定价研究

Seat、usage/credits、work/action、outcome 和 hybrid 都是候选。Token 是内部成本单位，不必直接成为客户价值语言。能可靠归因和审计的结果可研究 outcome；归因困难时研究 work unit；复杂服务可研究 base + usage/work + 有边界的高价值模块。

没有确定金额、计费方式或订阅承诺。2026-11-06 已单独确定公开原创文档采用 CC BY-NC 4.0，商业使用须另行取得授权；这不是商业产品定价决定。按提醒数收费可能鼓励噪声，按消息数收费可能鼓励无效对话，必须让商业激励与“少打扰、真闭环”一致。[S04 §11–12]

Billing Metric 用来结算，Value Metric 用来证明续费/扩容；不能混成“节约多少就必然按百分比分成”。先有基线再谈 ROI。[S04 §13]

## 6. 单位经济性与服务风险

收入应对照模型/基础设施、实施、人工复核、支持、连接器维护、获客和退出/迁移成本。FDE/企业改造可提供收入与领域学习，但不默认是终局产品形态；每客户独立 fork 会形成高成本服务依赖。[S04 §17–18、22–23]

每个项目应沉淀合法可复用的 Domain Knowledge、Workflow/Role/Policy Template、Connector、Eval、Delivery Playbook 或 Kernel 改进。核心检验是 Implementation Hours per New Organization 是否下降，不是仓库或模板数量。

交付前界定 scope、知识产权、知识转移、客户自主性、退出、复用边界和回馈核心的方式。“项目是采矿，产品化是冶炼”不允许把客户秘密当作可复用矿产。

## 7. 商业形态仍未决

Vertical SaaS、AI Transformation/FDE、Context Platform、AI-native ERP/OA、Agent Context/Control Plane 都是曾讨论的候选。“早期 B+A、积累 C、长期 E”只是工作假设。Open-core、“Open Context, Paid Coordination”、托管/私有部署分层均未获正式战略批准。[S04 §15、21]

## 8. 需要证伪的关键命题

- 客户愿意为具体闭环付费而不只是体验 AI。
- 系统可降低净负担，不迫使员工重复维护所有 Context。
- 第二家客户可以更低工时交付。
- 更换模型/Agent 后业务 Context 保持连续。
- 连接器和人类兜底成本不吞噬毛利。
- 客户有理由购买而不是用编码 Agent 自建简单功能。
