## 2. 继承的历史原则

以下是来源中已有的原则，本次保留为设计约束参考；没有把它们伪装为用户在本轮逐项批准的规格。

| 原则 | 历史依据 | 当前用法 |
|---|---|---|
| 单节点价值先于网络价值 | 历史 D18–D26、D43–D45 | 先选真实工作流，再研究组织网络 |
| Context 有范围、时效、来源与治理 | D28–D29 | 维护业务状态，不把聊天记忆当真相 |
| Personal/Role/Organization 连接不合并 | D30–D34 | 权限、交接、撤权与个人边界 |
| 权威行动逐步放开，报告来自状态投影 | D35–D39 | 生成与执行分开，完成需核验 |
| Agent 和共享工具可替换 | D40–D42 及更早技术原则 | 不预锁模型、Harness 或 MCP |
| 现场交付形成下一次可复用资产 | D50–D52 | 用第二次工时与维护证据验证 |

详见[历史决策](历史决策与观点演变.md)和[历史来源清单](../99-来源与维护/来源索引.md)。D46 描述目标客户原有业务已成立的画像，不能作为本项目已获商业验证的证据。
