# 开放问题与研究路线图

状态：研究积压与建议门槛，不是时间承诺或已批准开发计划。依据：S01 §4–5、S04 §22–23、S05 §23、S06 §21、H07–H08。

当前执行建议见[整体方案 v0.2](../plans/2026-11-04-project-plan-v0.2.md)，各项确认程度见[整合决策与待验证假设](整合决策与待验证假设.md)。本文保留研究问题，不把所有研究项纳入首轮范围。

## 1. 优先开放问题

| 问题 | 需要的证据 | 不能先假定 |
|---|---|---|
| 第一类工作和用户是谁？ | 任务日志、访谈、频率、当前代价和支付链 | 通用平台天然有需求 |
| 哪个场景能降低净负担？ | 端到端对照、纠错与维护工时 | 自动抽取越多越好 |
| 什么是权威事实源？ | 系统责任、来源冲突与时效样例 | 最新聊天就是正确事实 |
| Identity/entity 怎样稳定？ | 同名、跨系统、误 merge/split 测试 | 模型知道就是同一个人 |
| 企业冷启动怎样做？ | 授权材料编译与人工确认成本 | 全量接入就会自动理解组织 |
| 模型如何安全行动？ | 权限、审批、幂等、失败恢复与回执 | Agent 会调用工具即可靠执行 |
| 本体/Domain Pack 如何升级？ | Schema 演进、旧语义解释与迁移测试 | 统一模型适用所有行业 |
| 权限如何贯穿推断与输出？ | 撤权、目的限制、侧漏/注入测试 | RBAC 或 Prompt 足够 |
| 什么值得打扰人？ | 漏报、误报、冷却、信任与净负担数据 | 互动更多就是更好 |
| 能否低成本复用？ | 第二组织实施工时及差异清单 | 模板多就等于产品化 |
| 买而非自建的理由？ | 客户比较、持续维护成本与愿付价 | 编码速度本身是壁垒 |
| 合适计费单位是什么？ | 可审计 work/outcome、成本、预算与续费 | 价值百分比天然可归因 |
| 谁授权、谁采购、谁负责？ | Buyer/User/Champion/Security/Procurement 的实际角色 | 老板同意就覆盖全部数据权利 |
| 退出和故障如何继续工作？ | 导出、模型替换、断网/服务故障演练 | 供应商永远可用 |

## 2. 近期：业务发现与最小证据

建议先选一个可接触且合法授权的流程，完成去敏流程/角色/系统图、基线、未闭环事项样本、最小成功标准和不可执行清单。业务处理优先，但实验最小安全边界同步确定。

输出：一份场景说明 + 一组固定评价任务 + 首个 MVP 选择记录。门槛：真实痛点、责任范围、数据准入和可度量完成态清楚。没有证据时不先造统一平台。

## 3. 接着：只读/草稿闭环

比较现有工具、简单规则和模型方案；实现来源到状态的可追溯投影，观察用户修正与净负担。用相同样本评估 OCR/ASR/解析/模型，不先绑定特定供应商。

输出：实验结果、错误分类、成本、适用边界和技术 ADR 候选。门槛：相对基线产生可信价值，并且来源、隔离和纠错机制可解释。

## 4. 然后：受控执行与第二场景复用

仅在获得具体授权且前序实验有效后，增加动作提案、批准、执行、回执和撤销/补偿，验证外部故障、重复请求和撤权。

随后选相似流程检验 Domain Pack、配置与 Kernel 改进是否降低交付工时。若每次都需重写，应调整抽象或缩小业务范围，而非继续扩张。

## 5. 远期：独立研究，不占用 MVP 默认范围

Context/Attention 双调度、Personal/Role/Organization 联邦、受限弱信号、组织涌现、Role Agent、跨企业协作、隐私计算和多节点仿真。每项都需要独立价值、隐私、安全、成本与可逆性验证；不能由单节点试点自动放行。

HA7CH 的公开项目与理念已有[专题研究](../research/2026-11-03-ha7ch-report.md)及[固定版本来源](../research/2026-11-03-ha7ch-sources.md)。其代码采用、许可与生产适用性，dbskill 许可、相邻 Context Network 项目的一手出处，仍按实际选型需要核验；不因名词相似直接采用代码或宣称原创。

## 6. 知识库下一轮补全

1. 完善已公开设计记录与外部一手来源之间的对应关系；没有公开证据的内容继续标为项目设计或待验证假设。
2. 针对会改变决策的市场主张重新访问一手来源，记录日期与版本。
3. 为每个验证建立证据与失败案例，不只保存成功演示。
4. 更新状态标签，明确哪些结论被接受、否定或替代。
5. 在任何公开发布或权限变化前重新审查隐私、客户数据和私人来源链接。
