# 愿景、定位与项目边界

状态：既有方向整理；长期架构是研究假设，不是产品批准。整理日期：2026-11-03。

2026-11-04 整合入口：[项目完整构想](项目完整构想.md)、[整体方案 v0.2](../plans/2026-11-04-project-plan-v0.2.md)。本文保留历史方向与出处；当前授权及假设见[状态登记](../06-决策与研究/整合决策与待验证假设.md)。

## 1. 母问题

研究如何让 AI 在企业真实业务中持续理解状态、维护承诺与依赖、协调人与系统，并在明确授权下完成可验证工作。目标不是在每个软件里加聊天框，也不是要求企业第一天替换 ERP、CRM、OA 和 IM。

长期闭环可表述为：现实事件 → 信息入口 → 有范围、有时效的业务 Context → Agent 理解/协调 → 人的判断或受控行动 → 新现实与反馈。现有系统既是 Sensor（输入业务证据）也是 Actuator（执行获准动作）；Context Runtime 是候选协调层，而非已建成平台。[S05 §1–3]

## 2. 产品价值应先落在具体工作

- 减少漏事、等待、反复录入和跨系统人工同步。
- 让未闭环事项、责任、期限、依赖和完成证据清晰可追溯。
- 人处理真正需要判断、承担责任或经营关系的部分。
- 业务增长不必等比例增加协调成本，是价值假设而非已验证收益。

先证明一个真实工作流有价值，再讨论平台、网络和组织演化。单节点必须独立成立，网络价值只能是增量。[S04 §2–3、7；S06 §0、16]

## 3. 研究位置

通用 Agent/模型可以成为入口；本项目潜在持久资产是领域语义、可信历史、业务状态、权限与来源、工作流、交付方法和评价集。Prompt 是策略表达，Harness 是可替换工具，不把聊天 UI、MCP 或某个模型当作已经成立的护城河。[S01 D27–D29、D41–D42]

“AI-native Company / Human-Agent Operating Layer”是长期工作术语。不能据此宣布已决定做 Context Platform、企业控制平面、AI-native ERP，或已经找到了无人竞争的市场。[S04 §21；S08 §34]

## 4. 与教育垂直项目的关系

早期垂直项目的认知外置、Open Loop、Today/Timeline、证据、低负担与受控写入思想可供方法论参考；其对象、数据模型、R1 manifest、技术栈和实现状态不能自动移植。

历史 R1 边界为单班主任、单班级、单学期、手工 roster、Record/Task、Today/Timeline、最小退出和 Agent 只读/内存草稿。企业 Runtime、多用户网络、Role Agent、多渠道消息接管、自动外发、绩效推断、跨 Context 联邦均不由长期愿景获得实现批准。[S05 开篇、§24–25；S14]

本仓库不是 早期垂直项目 R1 的完成度报告，不沿用旧项目的测试结果证明企业能力已实现。
