# Attention、Context 网络与组织演化

状态：长期探索设想；未实现、未证明市场有效，不是企业 MVP 的默认范围。依据：S03、S05 §6–11、S06、S07。

## 1. 双调度器

Context Scheduler 决定某 Agent 为当前任务应该知道什么；Attention Scheduler 决定什么值得进入人的注意力。大上下文窗口不消除身份、目的、权限、时效和信息噪声问题。

Attention 的目标不是停留时长或消息数量，而是重要事项不遗漏、误打扰少、上下文切换成本低、信任可维持。Silence is a successful output。系统解释为何提醒时，也只能使用用户有权看到的证据。

## 2. 从直接消息到 Shared Artifact

候选协作路径：某 Actor 行动 → 在共同授权文档、邮件、工单或日历留下痕迹 → 产生受限信号 → 接收者结合本地 Context 决定是否关注。

Stigmergy 是通过环境痕迹间接协调的既有理论，不是本项目原创发明。与显式 A2A 协商相比，该机制希望减少消息洪流，但效果、安全性和成本仍需实验。

## 3. 不变量

1. 私人 Context 的主权优先于连接。
2. Signal 不等于 Content；无权读取的内容不能通过提醒、解释或排名侧漏。
3. 优先使用双方原本都有权访问的 Shared Artifact。
4. 外来信号只生成候选，接收节点拥有最终 Attention 决策。
5. 提醒、推断或“等待别人”不等于对方已接受责任。
6. 不能因组织正式化而吞并过去的私人历史。[S14 关键决策 19–25]

“弱信号更安全”本身也待验证：频率、存在性和时间变化可能泄露关系或私有事实；必须测试推断攻击、聚合泄漏、撤权后的残留与信号放大。

## 4. 自下而上的组织假设

单节点独立价值 → 重复微协作 → Shared State / 隐式关系 → 治理需求出现 → 经确认的组织正式化。与 Top-down 企业授权接入是兼容路线，不是已验证必经过程。

系统观察到相似模式不等于有权建立组织、合并用户或自动邀请第三方。Organization Emergence Threshold、Context Density、Organizational Gravity 都是研究标签，尚无稳定公式或产品标准。[S04 §4–5；S06 §8–10]

## 5. Role Agent 与岗位持续性

候选模型：Role = Persistent Role Context + Role Agent + Human Occupant。岗位的输入、输出、责任、授权、SLA、升级与风险契约可持续；任职者可以变化。Continuous Handoff 不是收集员工全部私人思考。

个人 Agent 与岗位 Agent 的磨合、动态工作分配、Human-Agent Composite Role 都是探索。招聘匹配、能力缺口判断和绩效推断属于高影响领域，不能因为存在 Context 就自动决策。[S06 §12–14]

## 6. 保留隐喻，不把隐喻产品化

Anti-feed、Cognitive Firewall、Context 数字资本、注意力货币、Agent Society OS 用于理解问题，不是品牌、正式协议、金融产品或区块链/Token 决策。多仓研究草图也不表示已创建生产仓库。[S07；S06 §18]

## 7. 候选实验

- 对同一组模拟未闭环事项比较固定提醒与上下文排序，测漏报、误报、总打扰和可解释性。
- 仅在合成双节点共享文档上生成信号，测试未共享信息不能从输出反推。
- 对受控模拟事件运行撤权、冷却、去重与拥塞场景。
- 在单节点价值成立后再研究组织化；没有收益或产生隐私泄漏则停止扩张。

以上实验为本次整理建议，未获实现批准。
