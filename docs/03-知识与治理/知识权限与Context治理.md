# 知识、权限与 Context 治理

状态：历史长期边界原则 + 候选工程约束。依据：S01 D28–D39；S05 §7–13、16、19–23；S06 §3–5、11。

## 1. 知识不只是内容库

企业知识包含术语与本体、制度与业务规则、流程、关系、事件、当前状态、正式决策及其证据。Context 必须 scoped / persistent / governed / temporal；聊天记忆、文档 RAG 和权威业务状态不是同一层。

建议最小知识记录：对象与范围、内容类别、原始来源、观察/生效/失效时间、记录者与确认者、权限、冲突状态、版本、生命周期和相关业务动作。此字段集合是整理建议，不是已选数据库 Schema。

## 2. 防止 AI 推断污染事实

| 类型 | 含义 | 升级条件 |
|---|---|---|
| Fact | 有可核验证据支持的事实 | 保留来源与适用时间 |
| Observation | 某人在某时的观察 | 不扩大为永久评价 |
| Claim | 某来源的主张 | 记录主张者，不自动视为真 |
| Derived Signal | 依规则导出的信号 | 可回溯计算依据与版本 |
| AI Inference | 模型推断或候选解释 | 经独立证据/人工确认，不自动晋升 |

知识冲突不是简单取最新文本。需综合来源权威、目的、有效时间、新鲜度、置信度和人工更正；旧结论被修正时保留历史，不用后见之明覆盖原判断。[S14 关键决策 11；S05 §23.6]

## 3. 所有权与共享层次

Private → 经明确治理的 Shared Artifact → 经正式确认的 Institutional Context。加入组织、签入软件或形成协作网络，都不代表历史私人内容被组织取得。

组织可以维护正式业务记录；私人 AI 对话、草稿、情绪、私人评价和个人注意力模式不能默认成为公司资产。部门、角色、项目、用途、时间和输出对象共同限定可见范围。数据可读不等于可用于新目的或可向别人输出。

One Reality, Multiple Authorized Projections：围绕同一现实对象按目的生成必要投影，不做“全员看见所有数据”的超级共享库。

## 4. 两个边界都要控制

- 输入边界：谁能读什么，何种目的，授权何时失效，旧 Context 是否可重新激活。
- 输出/行动边界：能产生哪些推断、能向谁展示、能代表谁执行何种动作，谁承担责任。

RBAC、ABAC、Purpose 和推断/输出政策是研究候选，不能只用 Prompt 声明“请保护隐私”。邮件、网页、PDF、客户文件等是内容与证据，不能自动变成指令或权限。外部内容里的提示注入须隔离。[S05 §23.4；S06 §11]

## 5. 生命周期与退出

Context 可 active、dormant、archived 或 revoked；前同事、已结束项目和旧政策不应永久进入当前推理。离职撤销 Binding，岗位合法 Context 留在组织，个人合法 Context 随人，不跨公司串用。保留更正、导出、迁移、删除/保留期控制与模型替换路径。[S05 §8、22–23]

业务连续性需要检验模型故障、连接器失效、供应商退出和客户迁移。可信壁垒应来自持续价值，不是阻止客户带走数据。

## 6. 报告与可观察性

业务事件和已确认状态先于报告；日报、周报是时间窗口的投影，不是新的事实来源。机器先重建状态，只对缺失/低置信度事项询问人员。

Business Telemetry 用于业务状态，Operational Telemetry 用于系统运行，Personal Cognitive Telemetry 默认不归企业。commit/消息数量不能推导员工价值；把痕迹用于考核会诱发行为扭曲，反而破坏 Context 真实性。[S01 D38–D39；S05 §15–17]

## 7. 本知识库的信息边界

只保存项目相关结论、去敏摘要和必要来源。不得写入凭据、客户联系人/账目/合同正文、未成年人数据、个人生活资料或私人聊天全文。私有仓并不等于可以无界收录。后续公开发布或更改仓库权限前，必须重新审查全部内容与来源链接。
